Python integration:
from display import start_display
process, environment, metadata = start_display(engine_config, runtime, engine)

DOUBLETAKE_DISPLAY_BACKEND: auto (default), xvfb, or xvnc.
auto selects Xvnc when its binary and an accessible render node are present,
requires a successful DRI3 query, and stops a failed display before Xvfb fallback.
Forced xvnc on GPU-free CI uses -rendernode '' and must not silently fall back.

The Xvnc display uses -rfbport -1, so it has no TCP RFB listener; no RFB UNIX
socket is configured. X11 TCP is disabled and MIT-MAGIC-COOKIE-1 authentication
uses the worker's private Xauthority. Existing x11vnc preview authentication and
its native-control viewonly guard remain unchanged.

Validation needed:
- ldd /usr/local/bin/Xvnc has no missing dependencies.
- Xvnc forced in native and diagnostic integration, including input/paste/close.
- CPU-only CI reports backend=xvnc; DRI3=false is expected without render node.
- Live Intel host reports backend=xvnc, DRI3=true, Intel GL renderer.
- Compare YouTube dropped-frame deltas and sender throughput before/after.
- Verify existing HEVC doorbell rendering, login persistence and TV audio.

Bookworm's tigervnc package is 1.12.0 (no new DRI3 support). The current
bookworm-backports amd64 Packages.xz has no tigervnc-standalone-server entry.
Trixie's package is 1.15.0+dfsg-2.1~deb13u1 and requires glibc >=2.38; copying
that Debian binary into bookworm is unsuitable. The official generic archive
avoids changing the runtime distribution or compiling a second X server.
